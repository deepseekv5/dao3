# 编辑器界面与命令

编辑器是这一层里唯一"造东西"的地方：左边选方块、中间看世界、右边改属性、底部读状态。
这一篇写清每个区到底放了什么、为什么这么放，以及**它做不到什么**——
因为"编辑器像不像 IDE"这件事，最后落在两个具体判断上：
**不认识的图标能不能用文字干**，以及**屏幕上的读数是不是真的**。

<a id="layout"></a>
## 布局：五个区 + 一条读数带

| 区 | 位置 | 放什么 | 尺寸 |
|---|---|---|---|
| 顶栏 `#topbar` | 顶部 | 工作区菜单（左）· 撤销/重做/撤销历史/存盘状态（中）· 世界库/协作/运行/发布（右） | 48px 高 |
| 方块库 `#libCard` | 左上浮动 | 地形/场景两组，3D 立方体缩略图 + 搜索 + 笔刷半径 | 230px 宽 |
| 工具条 `#editToolbar` | 顶部居中 | 6 个高频工具 + 「更多」收纳 11 个批量/几何工具 + 一组视图开关 | 内容宽 |
| 右面板 `#rightPanel` | 右侧 | 模型/界面树 + 属性卡 | 300px 宽 |
| 状态栏 `#hud` | 底部通栏 | 当前工具 · 工作区 · 坐标 · 选区 · 体素数 · 世界名 ‖ 诊断 · 存盘 · F1 命令 | 24px 高 |
| 坐标罗盘 `.view-gizmo` | 视口右下角 | 世界三轴的屏幕朝向；点轴端点切到该方向的标准视角 | 64px 见方 |

工具条**不是**按整幅视口居中的：右边 300px 被面板占着，居中就会压在"模型/界面"那两个 tab 上
（实拍里它们被吃掉一半）。所以它居中在两块面板之间的净空里，算式写在 CSS 注释里。

顶栏每个图标都必须有自己的 `id`——没 id 的按钮就是"没人接的那一个"。这条写进了断言，
因为这里曾经真躺着两颗假图标：一颗写着「协作」、点上去提示"本地单机版暂未开放"，
而它右边就是能用的协作按钮。

颜色也只有一个来源：`editor.css` 顶部那一份 `:root`。换主题那次只换了 token，
内层还留着上一套主题的 45 处硬编码色（代码区、方块格子、行号槽、四五种"错误红"各写各的），
于是同一个界面里有两种底色、四种灰阶——看着像三个产品拼起来的。
现在 `:root` 之外一个有彩色字面量都不剩，这条写成了断言（`npm run test:ide` 直接数）。

三组例外是刻意的，都在 `:root` 里单独成组：`--syn-*` 是代码着色（编辑器主题和界面主题
本来就是两套，把注释调成霓虹青会读得累）、`--ok-dim` 是"活着"的绿、
`--run` 是运行按钮的绿；血条渐变同理保留。坐标罗盘的 X 红 / Y 绿 / Z 蓝
写在 `view-gizmo.js` 里，因为颜色在那里是"哪根轴"的唯一编码，换成主题色就没人读得出来。

<a id="batch"></a>
## 拖拽与批量：一次操作 = 一步撤销

搭建那一排工具全是同一套三段回调：`onDown` 起点、`onMove` 拖动途中、`onUp` 终点 + 提交。
**提交才是写世界的那一步**——`History.commit()` 才调 `world.set()`，所以一次拖动撤销一步，
而不是拖过 200 格就要按 200 次撤销。

`onMove` 只在左键按住时派发。这一条看着显然，却正是"拆不掉方块、批量建造没反应"的来源：
Chrome 在 `pointermove` 上把 `e.button` 报成 **-1**（哪怕左键正按着），而派发处写的是
`if (e.button !== 0) return`。于是所有工具的 `onMove` 静默失效，`onUp` 提交的是空变更，
`commit()` 遇到空数组直接 return——按下去、拖开、松手，画面什么都没发生。
现在的门控是：按下与松开看 `button`，拖动看 `buttons`。

按住 Shift 是"同一个工具的另一种形状"，不新增按钮：

| 工具 | 不按 Shift | 按住 Shift |
|---|---|---|
| 盒 / 盒删 | 实心（挖）整块 | 只做外壳 |
| 球 / 空心球 / 半径笔刷 / 圆柱 / 空心柱 | 半径 1 | 半径 3 |
| 阵列 | 2×2 | 3×3 |

线/盒/球/圆柱/阵列/平整这 11 个批量与几何工具收在工具条的「更多」里，随时可达：
命令面板搜"用盒"、或者展开「更多」（展开状态记在本地，这是人的习惯，不该每次开都重新问）。

顺带一条从同一处抓出来的：阵列原来份数和偏移都取同一个 `s`，`s=1` 时唯一那份
被"跳过原点"的判据略过，一次点击什么都不做；现在偏移按选区自身尺寸算，副本紧贴原件。

<a id="statusbar"></a>
## 状态栏：读数必须是真的

底部那条 24px 通栏是这一轮新加的。它左边读"现在能干什么"（工具、工作区、光标格坐标、
选区尺寸、世界体素数、世界名），右边读"有什么问题"（诊断按严重度计数，点一下跳到下一个问题，
有错误时整段转成错误色）、存盘状态和命令面板入口。

三个决定值得写下来：

**刷新走 250ms 轮询，不在每个改动点埋一次 `update()`。** 改动点会随功能一起长，逐个埋点
必然漏掉后来新增的那个，而漏掉的表征恰好就是这条要修的 bug 本身——读数停在旧值，
看起来像"状态栏坏了"。轮询的代价是最坏晚半拍，收益是新控件不用回来改这里。
`set()` 只在值真的变了才写 DOM，所以它不引起重排。

**存盘状态抄顶栏那个节点，不自己判 `dirty`。** 写它的地方有手动保存、自动保存、加载世界三处，
状态栏再自己算一次就会出现"顶栏说已保存、底栏说未保存"。

**分隔点用 CSS 的 `.sb-seg + .sb-seg::before` 画。** 写成一排 `<span>·</span>` 时，
中间任何一段 `hidden` 掉都会留下一个孤立的点。

<a id="palette"></a>
## 命令面板：第二条通路（F1 / Ctrl+Shift+P）

工作台一屏有 115 个可见控件。上一轮把工具条收成"6 + 更多"，那只是把噪音挪了个位置——
真正的问题不是"东西太多"，是**没有一条不用找图标就能干活的通路**。有了面板，图标可以更少，
因为所有动作都还能敲两个字出来。

49 条命令分 9 组：切换工作区 / 工具 / 视图 / 编辑 / 选区 / 运行 / 发布与协作 / 跳转 / 帮助与设置。
输入支持子序列匹配（打"运g"能中"运行游戏"），上下键选、回车执行、Esc 或点遮罩关闭。

两条实现约束：

- **命令一律转调现有控件的 `click()`**，不在这里重写一遍行为。两处实现必然漂移，
  而漂移的症状是"从图标点进去对、从面板点进去不对"，最难查。
  只有确实没有对应控件的（跳到第 n 行、上下个问题）才自己实现，并且复用脚本页暴露的同一套函数。
- **找不到入口就明说**（`找不到入口：#xxx`），不静默。一条按了没反应的面板比没有面板更糟。

它顺手解决了一个真实缺口：折叠掉的 11 个工具（`.ft-extra`，默认 `display:none`）
从面板照样调得到，调中之后工具条自动展开把那一项露出来。
选区那几个动作（复制/粘贴/副本/删除/清除）原本只有快捷键，而 `main.js` 里它们
"没选区就 return"——从面板点进去什么都不发生会被当成面板坏了，所以条件不满足时把理由说出来。

<a id="script-ide"></a>
## 脚本页的 IDE 层

脚本工作区单独说，因为它参照的是官方 ArenaNext 那支编辑器增强脚本，
核心不是 Monaco 而是**诊断看得见 + 光标在哪就能对哪段代码下手**：

- 行内装饰：出错的行画底边，行号槽打 ● 错误 / ▲ 警告 / ○ 提示；
- 问题面板：控制台旁边的一个 tab，按严重度筛、点一条跳过去、有错误时给「交给 AI 修」；
- 行内动作条：报"当前在哪个函数"，挂 解释 / 加注释 / 优化重构 / 纠正错误；
- 诊断的两个来源是真的：语法走 V8（`new Function`），规则走 `lint.js`。
  「检查严格度」面板里跑不了的项（TypeScript 的隐式 any / 隐式 this）**禁用并写明原因**，不做哑开关。
- **控制台是一份日志，不是一行状态文字。** 以前所有输出都往同一个 `textContent` 上写，
  一条覆盖上一条、报错还会把刚才那批 log 抹掉——看不了历史就没法拿两条输出互相比对。
  现在条目化（时间 + 严重度 + 正文），输出 / 警告 / 错误 三个筛选项带真实计数，
  连续重复折成 `×N`，能清空，带行号的报错可以直接跳。
  运行态的 `console.*` 与引擎内部报错也抄一份进来：跑完一局回到编辑器，那几行报错还在原地。
  计数报的是"来过几条"而不是"现在有几行"；筛选与 pane 的可见性都写成容器上的
  `data-*` 交给 CSS，避免"JS 逐个 hidden"那种后来加的东西不在清单里的漏。

语法错**不报行号**：V8 在 `new Function` 抛的 `SyntaxError` 里给的是构造器自己的位置，
报出来是一个稳定的错误行号，比不报更坏。所以那一类在面板里显示"整份文件"。

<a id="history"></a>
## 撤销历史

顶栏撤销旁边那个按钮打开一张步骤清单：每步叫什么、改了几格、当前停在哪一步（高亮），
被撤销掉的那些压暗但留着——点一下就 redo 回来。

之所以要有它：只有 Ctrl+Z 的时候，撤销是"盲按直到看起来对"。一次拖拽、一次脚本执行、
一次 AI 建模都算一步，按过了头得反向按，而人并不知道自己退了几步。

中文名从 `TOOLS[key].name` 取，面板里不抄第二份；栈的变化走 250ms 重读，
不在那二十多个 `commit()` 调用点各埋一次通知。

<a id="inspector"></a>
## 属性面板的手感

- **按住属性名横向拖 = 改数值**（Unity / Blender 那套）。一格 = 一个 step，
  Shift 走 0.1 个 step 做微调，悬停时光标变成左右箭头告知可以拖。
  拖的是**标签**不是输入框——输入框还要用来打字，把它整个变成拖拽目标就成了"点不进去编辑"。
  拖动只改 DOM 并派发 `input` + `change`，写回 state 的那条路已经存在，这里不写第二份。
- **滚轮改值**只在指针停在数值框上时生效；停在列表里就是正常滚动。
- 位置 X/Y/Z 那三个框只表示"选中模型的坐标"。它们曾经每帧被写成鼠标拾取到的体素，
  看着能拖、实际每帧被覆盖，拖了也白拖——那是同一类问题：**能操作的样子**和**真的能操作**不是一回事。
- **选中模型会出现变换手柄**，模式在属性卡头部那一排（移动 / 旋转 / 缩放，Shift+G 循环，
  记在本地）。移动是三根箭头加中心球：**拖箭头 = 只沿那一根轴走**，**拖中心球 = 在屏幕平面里自由挪**。
  旋转是三个环加一个外圈：**拖环 = 绕那根轴转**，外圈绕视线转；按住 Shift 吸附 15°。
  缩放是轴端的小方块加中间一个：**拖端头 = 只改那一根轴**，拖中间立方体等比，Shift 吸附 0.25 倍。
  转与放的结果写进 `object.quaternion` / `object.scale`，保存链路读的就是这两个，
  所以存盘、撤销历史、属性卡上的旋转/缩放滑杆看到的是同一份值（松手会刷一次属性卡，
  否则下一次拖滑杆会把手柄刚改出来的结果覆盖回去）。
- 手柄的三个实现决定：**命中判定按屏幕像素**，不按网格求交——画多大就是多大、
  容差不随相机远近漂，而旋转环那种细长形状靠射线根本点不稳；
  **尺寸按"屏幕上多长"反算**世界长度，拉近拉远都是那么大；
  **`depthTest` 关掉**，被方块挡住也能拖（不能拖的手柄会被当成坏了）。
  指针事件从 `main.js` 的 `toolDispatch` 最前面过一道，手柄接住就不再走工具——
  否则按住箭头拖一次会同时放下一排方块。
- **拖动状态一定收得回**：在手柄上按下、却在视口外松手时，视口收不到那次 `pointerup`。
  兜不住的话 `drag` 一直挂着，之后每一次工具拖动的 move/up 都被吞掉，
  症状正是"突然全都失效"，而且只能刷新页面恢复。所以除了视口，
  `window` 上的 `pointerup` / `pointercancel` / `blur` 都会结束手势，
  而拖动中收到一次"左键已经松开"的 move 也就地让出。

<a id="limits"></a>
## 做不到什么

写清楚边界，免得对着一个不存在的功能找半天：

- **编辑器内核还是 `textarea` + `<pre>` 覆盖层**，不是 Monaco。零第三方运行时依赖是前提，
  Monaco 是几兆的构建产物。代价：没有多光标、没有分屏、没有真正的语法着色（只有装饰行）。
- **没有 `world.` 成员补全。** 官方 API 签名数据在 `public/data/api-spec.json` 里，
  但把它接成补全弹窗是另一件事，没做就是没做。
- **诊断是正则加 V8，不是类型检查。** 报得准的范围只有那几条规则；括号不配对时行号会漂，
  所以那种情况下只报语法错，不报规则。
- **状态栏是 250ms 轮询**，不是事件驱动：拖拽过程中的瞬时值可能读不到，读到的一定是最近的稳定值。
- **命令面板不新增能力**，它只是现有按钮的第二条通路。没有按钮、也没接进来的动作，
  面板里同样没有——这是刻意的，避免面板变成第二个需要维护的行为实现。
