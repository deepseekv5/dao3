# AI 能力：写脚本与生成体素模型

这篇讲两件事：**怎么配**，以及**你交给它的密钥会经过哪些手**。
所有数字都是本机实测的（`node test/ai.mjs` 94 条 + `test/e2e.mjs` 里代理那 6 条），
不是照着设计稿写的。

> AI 是**可选**能力。不填接口，编辑器一切功能照旧；填了也不会多出任何官方 API——
> 它只是把自然语言翻译成官方那套脚本接口，产出仍然要你自己看懂、自己负责。

## 三个入口

| 在哪 | 做什么 | 产出落在哪 |
|---|---|---|
| 顶部「脚本」→ 右上「AI 生成」 | 按需求写一份地图脚本，或改写当前这份 | 点「新建文件 / 写入当前文件」才进 `meta.scripts` |
| 顶部「脚本」→ 右上「AI Agent」 | 给一个目标，它自己规划、动手、验证、按报错自修，跑完整条链 | 每一步都直接改工程，但**全部进撤销栈** |
| VOXA 菜单 → 「AI 生成模型…」 | 按描述拼一个体素模型 | 点「写进工程」才加部件（先 `snapshot` 进撤销栈） |

一次性生成那两处必须**人点一下才落地**，中间有预览。原因很直接：模型会自信地产出
跑不通的东西，静默写进你的地图或工程，比它写错更难查。
Agent 那一档是**你明确交出控制权**的：它自己就动，但每个动作都在小窗里逐条留痕、
没有步数上限、随时可中止，且都能用 Cmd-Z 退回去。

## 配置

「接口设置」四个字段，存在这台设备浏览器的 `localStorage.dao3_ai_config` 里：

| 字段 | 默认值 | 说明 |
|---|---|---|
| 接口地址 | `https://api.openai.com/v1` | OpenAI 兼容 base，填到 `/v1` 为止；实际请求 `${baseUrl}/chat/completions` |
| 模型名 | `gpt-4o-mini` | 任意字符串，直接透传 |
| 密钥 | 空 | `password` 输入框；**必填项里只有它没有默认值** |
| 温度 | 0.4 | 夹在 0..2 |

任何 OpenAI 兼容服务都能用：官方、One-API 一类中转站、LM Studio、Ollama 的
openai 兼容端点。填完点「测试连接」，它发一句"只回复两个字"并显示回来的模型名。

### 改动即时保存，没有「保存」按钮

面板上四个字段**边填边存**（去抖 150ms 写 `localStorage`），标题旁会出现
「已自动保存 hh:mm:ss」，关掉面板时再兜底存一次。原因很具体：密钥这件事一定会
分几次改（贴地址、试模型名、换一个 key），而"改了没点保存就去点测试"会拿**旧值**
发请求——报出来还是上游的错，看着像地址填错了，其实是自己没点那个按钮。
自动保存把这类假故障直接消掉。所以按钮是「关闭」而不是「取消」：
留着「取消」会撒谎。

想收回就点**清除密钥**（只清密钥，其余设置保留）。

### 拉取模型列表

**拉取模型列表**会走 `/api/ai/models` 去问 `/models`，把结果填进模型名的下拉建议里
（仍可手输）。它同样只经本地代理——浏览器直连要赌对方开 CORS，而且密钥会离开这台设备。
上游没有实现 `/models`（404/405）时回报的是"这个服务不提供列表，手输即可"，
**不算你配置错了**：很多兼容网关确实没做这个端点，混成鉴权失败会让人反复重填密钥。

## 密钥的行程

```
你的浏览器 ──(127.0.0.1)──> node server.js ──(https)──> 你填的那个地址
```

- **只存本地**：不进地图数据、不进 `.zip` 项目包、不进导出物。`check-distribution`
  的凭据扫描会连 `sk-…` 形态一起查，密钥一旦被写进任何分发面就会红。
- **只走回环**：`/api/ai/chat` 在处理前先验 `req.socket.remoteAddress` 是不是
  `127.0.0.1/::1`。这个端点会朝调用者指定的地址发请求，不挡外来来源就等于
  给全网开了一个免费代理——用 `HOST=0.0.0.0` 起服务时，局域网里别人打它只会拿到 403。
- **不落日志**：`server.js` 全库没有一处打印 `req.url` / `req.headers` / 请求体，
  代理这段也没有。密钥走**请求体**而不是请求头，就是为了别混进任何 access log。
- **错误回显先打码**：上游 401/500 的原文会转给前端，但先过一遍 `scrub()`——
  有些网关会把 `Authorization` 原样回显在报错里。实测：

  ```
  上游 401：bad auth: Bearer ••••
  ```

- **地址里不许塞凭据**：`https://user:pass@host/v1` 直接 400。这种写法会让凭据
  绕过统一的鉴权头、还会出现在错误文本里，密钥必须走密钥框。
- **不许指向本服务**：上游 `host:port` 与请求的 `Host` 相同就 400，防自环。
  注意比的是**主机+端口**——只比主机会把同一台机器上的 LM Studio / Ollama 全误杀
  （第一版就犯了这个错，导致 127.0.0.1 上任何端口都被当成"指向自己"）。

请求体上限 4 MB、消息最多 40 条、单条最多 20 万字符、上游超时 180 秒。

## AI 写脚本

它被允许写三种东西，由界面上的「目标 × 端」决定：

- **服务端脚本**（`index.js` 之类）：全局是 `world / voxels / resources / storage / db /
  rtc / analytics / gui / randomPick / getEntityBounds` 加一批 `Game*` 枚举。
- **客户端脚本**（文件名含 `client`）：全局是 `world / navigator / ui / input / screen /
  media / call / callAsync` 加 `UiBox / UiText / …`。
- **方块沙箱**（编辑器「运行」按钮执行）：全局只有 `sb / Math / console`，
  `sb.set/del/block/box/sphere/clear/count/size/log`。

关键设计：**它被告知的是全套开发规范，不是一份成员名清单**。
只给名字是不够的——名字不带单位、不带端、也不带"这个成员我们其实没实现"，
而恰恰是这三类信息决定生成的代码能不能跑。规范由 `public/js/ai-spec.js` 单点组装，
五个部分各自有防腐措施：

| 规范内容 | 来源 | 为什么不能手抄 |
|---|---|---|
| 逐个成员的签名 + 官方中文说明 | `public/data/api-spec.json`（由 `npm run build:api-ref` 从官方 `d.ts` 解析） | 手抄会在下一次 audit 之后静默过期 |
| 可用面 = 官方全集 ∩ 本实现到位的 | 同上，`tracked` 类才谈实现 | 过期的清单比没有清单更坏 |
| **禁用清单**（官方有、我们还没有的） | 规格里 `i === 0` 的成员现算 | 不明说，模型就会去调一个 `undefined` |
| 计时与单位（64ms/tick、速度 0.22/0.4、重力 −0.1、配额 4096、踏步 0.55） | **直接 `import` 自 `gapi.js`** | 出现第二份数字，就有一份会先腐烂 |
| 与常识相反的官方语义（`sunPhase` 是相位不是小时、服务端颜色 0..1 而 UI 颜色 0..255、`searchBox` 是全包含、`entity.id` 是名字…） | `ai-spec.js` 的 `PITFALLS`，手写 | 语义没法自动生成，但每条带 `api` 键，`test/ai.mjs` 会断言它指向的成员真在规格里 |

实测体量：服务端规范 45.7KB（22 个核心类逐个成员带签名，其余 78 类给成员名）、
客户端 8.2KB、方块沙箱 1.7KB。服务端那份偏大是有意的——「告诉模型所有开发规范」
和「省 token」是相反方向的两个目标，这里选择前者，并把字符数与 KB 数直接标在界面上，
让你自己判断要不要拿去喂一个上下文很小的本地模型。

方块名同理，从图集按类别各取几个，不塞全量 383 个。

### 「看规范」按钮

抽屉底部的**看规范**会把这一次真正要发出去的 system 文本原样显示出来，
附带类数与禁用项数。它不是文档截图，就是那次请求的内容：
`test/e2e.mjs` 会同时读界面显示的规范和打到本地的实际请求体，要求两者**逐字相同**——
否则这个按钮只是给人看的好看东西，模型其实没收到。

### 多轮、报错回喂、语法预检

- **再改一轮**：一次生成会保留这轮对话（system + 最近 8 条），所以你可以接着说
  "把播报改成屏幕右上角"，而不用重述需求、也不用赌模型能猜回上一版。
- **带上报错**：把控制台里最近一条运行报错贴进需求框。不自动贴是刻意的——
  自动贴会盖掉你刚写的字，而且不是每次报错都想让 AI 介入。
- **语法预检**：模型返回的代码先编译一次再给你。语法不过时两个「写入」按钮是灰的，
  而编译器的原话会直接回喂给模型。少了这一步，你要白等一次"运行→报错→重发"的往返。

## AI Agent 全自动小窗

脚本界面的**AI Agent** 是另一档：你给一个目标，它自己规划、自己动手、自己验证、
按报错自己修，跑完再交小结。它是一个**可拖动的浮层**，不是全屏抽屉——
一跑就是十几轮、几十秒到几分钟，你得能同时看到世界在长出什么，也要能随时中止。

### 动作面照官方 `apc` 的命名

动作名一律是 `<组>.<动词>`：`project.info` / `project.create` / `map.save` /
`map.resource` / `script.list|get|upload|rename` / `storage.set|get|list|remove` /
`blocks.edit` / `model.build` / `entity.add` / `build.check` /
`runtime.start|status|logs|stop` / `scene.capture` / `project.export` / `plan.set` / `finish`。
另有五个社区动作不走 `apc` 命名（官方 CLI 没有这一层）：
`community.who` / `community.publish` / `community.feed` / `community.comment`，它们只碰本地社区。

依据是官方 CLI 的 `apc script upload <project> <side> <entry>`、`apc storage`、
`apc runtime start|logs`、`apc scene capture`、`apc project info`，
以及官方 `engine-openapi-mcp` 的 `script.saveOrUpdate` / `storage.*` 那套工具名。
**只对齐命名与参数形状，不搬它们的代码**（engine-openapi-mcp 仓库没有 LICENSE）。


### 交付核对

`finish` 那一行下面会自动附一段**程序自己量出来的**清单，不是模型的小结：

```
— 交付核对 —
方块 1,523,683 · 模型/实体 200 · 区域 1 · HUD 部件 1
脚本 index.js(235行/server)、clientIndex.js(1行/client)、agentMade.js(1行/server)
已导出项目包 .zip（可转交的交付物）
⚠ 缺口：没有 runtime.start，脚本没真跑过、行为未验证
```

为什么要单独核一遍：全自动最容易骗人的地方就是"它说自己完成了"。
小结里写"已实现赛道与计分板"，实际可能一个方块没盖、一次都没存盘。
所以核对只看能量到的东西——方块数、区域数、HUD 数、脚本清单、有没有存盘导出——
并把缺口明写在最后。它不评价"像不像个好玩的游戏"，那个只有你玩过才知道。

创作动作面因此扩到：`project.create` / `map.save` / `blocks.edit` / `model.build` /
`entity.add`（触发盒）/ `ui.add`（HUD）/ `zone.add`（区域触发器）/
`settings.set`（游戏规则与世界物理）/ `project.export`（.zip 交付物）。

为什么值得对齐：模型在文档与训练数据里见过的就是这套名字。自己另起一套
（`inspectWorld` / `writeScript` / `playtest`）等于凭空加一次映射失败——它会输出
`script.upload`，然后收到一句"不认识的动作"，白烧一轮。旧的驼峰写法仍通过别名表
归一化，两种都能用。

### 端必须显式声明

`script.upload` 一定要给 `side: server | client`，这是官方契约。本实现按文件名判端，
所以工具会把 `side=client` 自动落到带 `Client` 的文件名上；而 `side=server` 配一个
含 `client` 的文件名会**直接被拒**——那种组合会静默按客户端跑，两边都觉得自己没错。

### 循环怎么跑

```
project.info → plan.set → 动手（blocks.edit / model.build / script.upload / entity.add）
            → build.check → runtime.start → runtime.logs → runtime.stop
            → scene.capture → map.save → finish
```

**界面照 Claude Code 的版式**：一个动作两行，`⏺ 动作名(参数摘要)` 在上、`⎿ 结果` 在下，
右边挂**这一步的耗时**；参数与长输出折叠在 `▸ 参数` / `展开完整输出` 里，点开就是
模型真实发出的原始 args（不是我们改写过的摘要）。`script.upload` 那一行还挂一个
**行级 diff**，`+` / `-` 直接看见它改了什么。顶部有实时计时、调用次数与 token 累计，
`plan.set` 发来的计划清单打在标题下方，随步骤推进逐项 ☑ 打勾。

为什么值得做成这样：全自动循环最怕黑箱。十几步跑完，如果界面只糊一坨日志，
用户无法判断它到底写没写过文件、有没有真的跑过测试，只能选择全信或全不信。
每一行都能展开看到原始参数与原始输出，"全自动"才是可以被监督的。

（一处诚实的限制：输出**不是流式**的。代理按整轮转发，所以 `⏺` 行要等这一轮
模型答完才出现，运行中的 spinner 也是这一轮的等待指示器。要做真流式得让
`/api/ai/chat` 支持 SSE，目前没做。）

**没有步数上限**——跑够为止。

唯一保留的自动停止条件是「卡住」，而且这是有意的：同一个动作带同样的参数连续失败 4 次，
或连续 12 步没有任何成功改动，就停下来等人，并把它每次收到的原始报错摊在你面前。
那种情况下继续跑只会无上限地烧**你自己的 API 额度**而不会再产出任何东西——
那不是全自动，是失控。`test/e2e.mjs` 里有一条专门钉它：让 mock 永远回同一个非法动作，
断言 4 次调用就自己停。

底线：

| 约束 | 值 | 超了怎么处理 |
|---|---|---|
| 步数 | **无上限** | 只有「卡住」才会停（见下） |
| 单脚本长度 | 20,000 字 | 拒收，让模型拆文件或写短 |
| 观察回喂长度 | 3,600 字 | 头 70% + 尾保留，中间标省略 |
| runtime.start 时长 | 1..200 tick | 夹到区间内 |
| 体素规模 | 见下表 | 越界图元丢弃 |

非法动作**不打断循环**：回一句带完整可用动作清单的拒绝，让模型下一步自己纠正。
`storage.*` 写的键与脚本里 `storage.getDataStorage(name)` 读到的是同一套 key
（`game.js` 的 `dataStorageKey` 是唯一来源，两处共用，避免"写进去读不出来"）。

所有改动都进撤销栈：盖体素走 `history.commit`，脚本表写入前留快照。
**Cmd-Z 是"Agent 把世界搞坏了"的正确答案。**

## AI 建模

让模型逐格报 2 万个坐标是行不通的——语言模型没有可靠的三维空间感，结果是糊成一团噪声。
所以约定它只输出**图元**，也就是体素美术打形体的真实做法：

```json
{"name":"小房子","parts":[{"name":"墙体","size":[24,20,24],"prims":[
  {"shape":"box","from":[4,0,4],"to":[19,11,19],"color":"#8a5a2b","shell":true},
  {"shape":"cylinder","center":[20,14,12],"axis":"y","radius":1,"height":6,"color":"#7d7d7d"},
  {"shape":"sphere","center":[12,6,12],"radii":[3,3,3],"color":"#f2c14e","emissive":6}
]}]}
```

只有 `box / sphere / cylinder` 三种形状，`y` 轴向上，坐标从 0 起。展开前有一道硬校验：

| 约束 | 值 | 越界怎么处理 |
|---|---|---|
| 部件框每轴 | 1..64 | 夹到 64 |
| 每部件图元数 | ≤ 400 | 多出来的丢弃 |
| 总体素数 | ≤ 60,000 | 超预算的图元丢弃 |
| box 跨度 | ≤ 部件框 + 2 | 见下 |
| `color` | `#rrggbb` | 坏值退化成 `#8a8a8a` |
| 不认识的 `shape` | — | 丢弃 |

跨度那条刻意分两种处理：**差一两格是模型最常见的 off-by-one**（`size:12` 却写
`to:[12,…]`），夹回来就是它想要的；而 `to:[99,99,99]` 这种离谱值夹回来会变成
"填满整个部件框"——实测把一座本来灰底座的小塔涂成了红块。所以跨度超过框 2 格以上
直接丢，计入预览里那句「丢弃 N 个越界或超配额图元」，而不是悄悄改你的设计。

全部图元都被丢掉时**明确报错**（`没有可用的部件：图元全部越界或超出配额`），
不返回一个空部件让你以为生成成功了。

展开是确定性的：同一个程序两次展开逐格相同，坐标必在框内、无重复
（`test/ai.mjs` 里直接断言这三条）。

上面这张表里的每个数字，同时也是**发给模型的提示词里的数字**——两边都取自
`ai.js` 导出的 `VOXEL_LIMITS`。这条是刻意钉住的：提示词写着"一个部件最多 40 个图元"
而校验器实际放行 400 个的话，被丢掉的那一半看起来像"AI 建模不行"，
其实是我们的规范自相矛盾。`test/ai.mjs` 会拿插值之后的成品提示词逐条对账。

## 网页体验版没有 AI

`/dao3play` 是静态托管，没有 `server.js`，所以没有 `/api/ai/chat` 代理，AI 入口也不在。
这是刻意的：体验版只跑官方赛车模板，没有编辑需求，而少了服务端就绝不该假装能调用。
缺代理时前端给的是能照着修的一句话，不是静默失败。

## 自己验一遍

```bash
node test/ai.mjs          # 94 条：解析、校验、展开、配额、规范、动作协议，纯离线不联网
npm run test:e2e          # 另外那批要真浏览器：代理 6 条 + 走真实 UI 的规范与 Agent 小窗
```

代理那 6 条不需要真密钥：测试自己在一个随机端口上起一个假的
`/v1/chat/completions`，故意让它在 401 里回显 `Authorization`，
再断言回到前端的文本里只剩 `Bearer ••••`。

规范那 15 条同样不联网：起一个只记录请求体的本地 mock，从编辑器里点真实的
「AI 生成」→「看规范」→「生成」，然后核对**模型侧收到的 system 消息**与界面显示的那份
逐字相同、user 消息带了端与需求、密钥没有混进 messages。
