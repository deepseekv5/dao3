# AI 能力：写脚本与生成体素模型

这篇讲两件事：**怎么配**，以及**你交给它的密钥会经过哪些手**。
所有数字都是本机实测的（`node test/ai.mjs` 27 条 + `test/e2e.mjs` 里代理那 6 条），
不是照着设计稿写的。

> AI 是**可选**能力。不填接口，编辑器一切功能照旧；填了也不会多出任何官方 API——
> 它只是把自然语言翻译成官方那套脚本接口，产出仍然要你自己看懂、自己负责。

## 两个入口

| 在哪 | 做什么 | 产出落在哪 |
|---|---|---|
| 顶部「脚本」→ 右上「AI 生成」 | 按需求写一份地图脚本，或改写当前这份 | 点「新建文件 / 写入当前文件」才进 `meta.scripts` |
| VOXA 菜单 → 「AI 生成模型…」 | 按描述拼一个体素模型 | 点「写进工程」才加部件（先 `snapshot` 进撤销栈） |

两处都必须**人点一下才落地**，中间有预览。原因很直接：模型会自信地产出跑不通的东西，
静默写进你的地图或工程，比它写错更难查。

## 配置

「接口设置」四个字段，存在这台设备浏览器的 `localStorage.dao3_ai_config` 里：

| 字段 | 默认值 | 说明 |
|---|---|---|
| 接口地址 | `https://api.openai.com/v1` | OpenAI 兼容 base，填到 `/v1` 为止；实际请求 `${baseUrl}/chat/completions` |
| 模型名 | `gpt-4o-mini` | 任意字符串，直接透传 |
| 密钥 | 空 | `password` 输入框；**必填项里只有它没有默认值** |
| 温度 | 0.4 | 夹在 0..2 |

任何 OpenAI 兼容服务都能用：官方、One-API 一类中转站、LM Studio、Ollama 的
openai 兼容端点。填完点「测试连接」，它发一句"只回复两个字"并显示回来的模型名。

## 密钥的行程

```
你的浏览器 ──(127.0.0.1)──> node server.js ──(https)──> 你填的那个地址
```

- **只存本地**：不进地图数据、不进 `.zip` 项目包、不进导出物。`check-distribution`
  的凭据扫描会连 `sk-…` 形态一起查，密钥一旦被写进任何分发面就会红。
- **只走回环**：`/api/ai/chat` 在处理前先验 `req.socket.remoteAddress` 是不是
  `127.0.0.1/::1`。这个端点会朝调用者指定的地址发请求，不挡外来来源就等于
  给全网开了一个免费代理——用 `HOST=0.0.0.0` 起服务时，局域网里别人打它只会拿到 403。
- **不落日志**：`server.js` 全库没有一处打印 `req.url` / `req.headers` / 请求体，
  代理这段也没有。密钥走**请求体**而不是请求头，就是为了别混进任何 access log。
- **错误回显先打码**：上游 401/500 的原文会转给前端，但先过一遍 `scrub()`——
  有些网关会把 `Authorization` 原样回显在报错里。实测：

  ```
  上游 401：bad auth: Bearer ••••
  ```

- **地址里不许塞凭据**：`https://user:pass@host/v1` 直接 400。这种写法会让凭据
  绕过统一的鉴权头、还会出现在错误文本里，密钥必须走密钥框。
- **不许指向本服务**：上游 `host:port` 与请求的 `Host` 相同就 400，防自环。
  注意比的是**主机+端口**——只比主机会把同一台机器上的 LM Studio / Ollama 全误杀
  （第一版就犯了这个错，导致 127.0.0.1 上任何端口都被当成"指向自己"）。

请求体上限 4 MB、消息最多 40 条、单条最多 20 万字符、上游超时 180 秒。

## AI 写脚本

它被允许写三种东西，由界面上的「目标 × 端」决定：

- **服务端脚本**（`index.js` 之类）：全局是 `world / voxels / resources / storage / db /
  rtc / analytics / gui / randomPick / getEntityBounds` 加一批 `Game*` 枚举。
- **客户端脚本**（文件名含 `client`）：全局是 `world / navigator / ui / input / screen /
  media / call / callAsync` 加 `UiBox / UiText / …`。
- **方块沙箱**（编辑器「运行」按钮执行）：全局只有 `sb / Math / console`，
  `sb.set/del/block/box/sphere/clear/count/size/log`。

关键设计：**提示词里的 API 清单不是手抄的**。它运行时从
`public/data/api-members.json`（官方全集）∩ `public/data/api-impl.json`（本实现有的）
现取，实测 72 个类。所以 `GameDatabase.sql`——目前唯一真缺的那个成员——
不会出现在清单里，模型不会被鼓励去调一个我们没实现的东西。
手抄清单必然在下一次 `npm run audit:api` 之后过期，而过期的清单比没有清单更坏。

方块名同理，从图集按类别各取几个，不塞全量 383 个。

官方常量（速度 0.22/0.4、跳跃 0.96、重力 −0.1 格/tick²、20 TPS = 64ms/tick、
`entity.id` 暴露的是实体**名字**）都写死在系统提示里，因为它要生成的代码必须
跑在[物理与单位制](physics.md)那套约定上。

## AI 建模

让模型逐格报 2 万个坐标是行不通的——语言模型没有可靠的三维空间感，结果是糊成一团噪声。
所以约定它只输出**图元**，也就是体素美术打形体的真实做法：

```json
{"name":"小房子","parts":[{"name":"墙体","size":[24,20,24],"prims":[
  {"shape":"box","from":[4,0,4],"to":[19,11,19],"color":"#8a5a2b","shell":true},
  {"shape":"cylinder","center":[20,14,12],"axis":"y","radius":1,"height":6,"color":"#7d7d7d"},
  {"shape":"sphere","center":[12,6,12],"radii":[3,3,3],"color":"#f2c14e","emissive":6}
]}]}
```

只有 `box / sphere / cylinder` 三种形状，`y` 轴向上，坐标从 0 起。展开前有一道硬校验：

| 约束 | 值 | 越界怎么处理 |
|---|---|---|
| 部件框每轴 | 1..64 | 夹到 64 |
| 每部件图元数 | ≤ 400 | 多出来的丢弃 |
| 总体素数 | ≤ 60,000 | 超预算的图元丢弃 |
| box 跨度 | ≤ 部件框 + 2 | 见下 |
| `color` | `#rrggbb` | 坏值退化成 `#8a8a8a` |
| 不认识的 `shape` | — | 丢弃 |

跨度那条刻意分两种处理：**差一两格是模型最常见的 off-by-one**（`size:12` 却写
`to:[12,…]`），夹回来就是它想要的；而 `to:[99,99,99]` 这种离谱值夹回来会变成
"填满整个部件框"——实测把一座本来灰底座的小塔涂成了红块。所以跨度超过框 2 格以上
直接丢，计入预览里那句「丢弃 N 个越界或超配额图元」，而不是悄悄改你的设计。

全部图元都被丢掉时**明确报错**（`没有可用的部件：图元全部越界或超出配额`），
不返回一个空部件让你以为生成成功了。

展开是确定性的：同一个程序两次展开逐格相同，坐标必在框内、无重复
（`test/ai.mjs` 里直接断言这三条）。

## 网页体验版没有 AI

`/dao3play` 是静态托管，没有 `server.js`，所以没有 `/api/ai/chat` 代理，AI 入口也不在。
这是刻意的：体验版只跑官方赛车模板，没有编辑需求，而少了服务端就绝不该假装能调用。
缺代理时前端给的是能照着修的一句话，不是静默失败。

## 自己验一遍

```bash
node test/ai.mjs          # 27 条：解析、校验、展开、配额，纯离线不联网
npm run test:e2e          # 含代理那 6 条：转发、401 打码、凭据地址、自环、缺密钥
```

代理那 6 条不需要真密钥：测试自己在一个随机端口上起一个假的
`/v1/chat/completions`，故意让它在 401 里回显 `Authorization`，
再断言回到前端的文本里只剩 `Bearer ••••`。
