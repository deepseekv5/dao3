# 社区层

编辑器造图，运行时跑图，社区层让人把图**发给别人**。这三件事里只有第三件是新的，
所以它也是最容易做假的一件：挂个列表页、放几张卡片，看着像社区，其实是个文件管理器。

这一篇写清楚社区层到底有什么、每个决定的代价，以及**它做不到什么**。

<a id="scope"></a>
## 一句话范围

账号、会话、关注、好友、地图/模型发布快照、广场与详情、点赞、评论、举报、
图片上传、封面生成、后台审查面板、多人联机与内置聊天——全部跑在**同一台本机 Node 进程**里，
零第三方依赖，数据是 `DATA_ROOT/community/` 下的 JSON 文件。

没有数据库，没有 Redis，没有对象存储，没有 CDN，没有邮箱验证，没有第三方登录。
这不是偷懒，是这条产品线的前提：数据不出机器。

<a id="identity"></a>
## 账号与会话

| 项 | 值 | 为什么 |
|---|---|---|
| 昵称 | 2–20 字符，中英文/数字/空格/`_`/`-` | 要能显示在角色头顶，太长会把 HUD 撑破 |
| 昵称唯一 | 大小写不敏感，改名不能撞别人 | 主页 URL 是 `/u/<名字>`，不唯一就寻址不了 |
| 密码 | scrypt，参数随凭据一起存 | 没有 bcrypt/argon2 可用，Node 内置只有 scrypt |
| 会话 | 随机 token，`HttpOnly + SameSite=Lax`，30 天 | 本机服务，但 SameSite 仍然要设，CSRF 面一样存在 |
| CSRF | 读接口下发 `ly_csrf` cookie，写请求必须原样带回 `X-CSRF-Token` | cookie 是 `Lax` 而不是 `None`，所以跨站表单打不进来 |
| 封禁 | `role: admin` / `banned` 标记，被封的账号只读 | 后台要能收得住捣乱的人，又不至于把机器锁死 |

会话校验顺带清理过期 token：`now() - createdAt > SESSION_TTL` 的会话在**任何一次请求**里
被碰到就删掉。没有后台定时任务，因为一个会自己醒的进程在这套架构里是额外复杂度。

<a id="publish"></a>
## 发布：快照，不是引用

这是社区层最重要的一个决定。

**发布不指向世界，而是把世界复制出去。** `POST /api/community/publish` 会把
`payload`、实体、脚本、素材目录整个拷进 `community/pubs/<pubId>/`，之后作者改自己的图，
别人点进去看到的还是发布那一刻的样子。

代价是磁盘：一张 4.5 MB 的图发一次就占 4.5 MB。换来的是两件更要紧的事：

1. 玩家点「开始游玩」不会拿到一张作者改到一半、正在报错的图。
2. 作者删掉本地世界，社区里那张图不会跟着变成 404。

再往上就是**版本**：重复发布同一个 `worldId` 会把上一份归档进 `versions`，
`version` 自增，详情页显示"版本 N"和每条更新说明（≤200 字）。
不做 diff、不做回滚合并——快照链已经够用，diff 会引入一套自己的正确性负担。

`kind` 有 `map`、`model`、`skin` 三种。模型走 `.voxa.json`，8 MB 上限，取回是**并进本地模型库**
而不是覆盖，同名会另存。

## 皮肤社区：第三种发布

皮肤既不是地图也不是模型：它没有"游玩"这个动作，也不该被塞进模型流里沉底。
所以它是第三种 `kind`，走同一套发布、点赞、评论、版本与举报，只换动作。

- **记录**：`.skin.json`（六块色 + 可选贴图 / 骨骼映射），≤64 KB。
- **资产**：贴图 PNG 与骨骼 GLB 以 base64 附件收进这份发布自己的 `.assets/`，
  记录里的路径被改写成 `/api/community/pubs/<id>/asset?path=…`。不改写的话，
  别人下载到的皮肤指向作者本机的世界目录，作者一删图就 404。
- **取用**：详情页的主按钮是「应用到我的角色」——写进**账号皮肤**，
  于是进任何一张图都这一身，联机时别人看你也是；不是"复制一份到这张图里"。
- **白名单**：外链资产、坏颜色、坏轴向、离谱缩放一律丢掉；认不出至少 6 根关节的
  记录不当它是骨骼皮肤。宁可退回纯色人偶，也不要半台机甲只躯干跟着动。
- 皮肤库面板里每张卡的「⋯」可以发布，工具条的「皮肤社区」可以取回：
  取回时资产会**复制进本图资产目录**，作者之后下架不影响你已经装上的这套。

<a id="surfaces"></a>
## 前端有哪几个面

路由是同一套壳（`community.html`）按 `location.pathname` 分派，`popstate` 重跑：

| 路径 | 是什么 |
|---|---|
| `/community` | 广场：精选位 + 导轨 + 分类 + 排序 + 搜索 |
| `/p/<pubId>` | 地图/模型详情：封面压标题、右栏动作与信息表、评论、"接下来试试" |
| `/u/<名字>` | 用户主页：横幅、头像、皮肤卡（人偶 / 贴图 / 真模型预览）、地区·性别·性格、关注/加好友/私聊、地图/模型/关注者/关注中/最近游玩五个 tab |
| `/friends` | 好友与关注：好友 / 请求 / 扩列 / 可能认识 / 通知 |
| `/me` | 自己的主页（未登录会跳登录框） |

广场的卡片是**图占绝对主导**的展厅读法：标题压在封面下缘的暗带上，
相框 16:10 用 `contain`——这些封面是体素小地图，`cover` 会裁掉一圈看不出是什么，
而 1:1 方框配 16:9 原图只剩上下两道黑带。

<a id="moderation"></a>
## 评论、审查与举报

评论 500 字上限，一层楼中楼（回复带 `to`），点赞去重按用户。
**未登录也给出一个禁用的输入框**，而不是"登录后才能评论"一句话——
位置先占住，用户知道这里能写。

文本进来先过 `screen()`：`block` 词表直接拒，`flag` 词表放行但打 `flagged` 标记，
后台面板按标记排序给人看。词表在 `community/mute-words.json`，改完 **mtime 变了就热加载**，
不用重启服务。

举报进 `reports` 队列，上限 500 条，超了丢最老的。后台能直接下架（`status` 从 `live` 改成别的），
下架的发布对所有读接口立刻不可见。

封面：发布时如果没带封面，服务端会用体素数据**离线渲染一张**（带邻接遮蔽的明暗），
所以不会出现"每张图都缺一个 404 占位"的场面。

<a id="social"></a>
## 好友、扩列与资料

社交动作大多发生在"正在做别的事"的时候：逛广场看到一个人、玩图时想喊一句、
收到请求想立刻回。所以它不是一个页面，而是**从右侧滑出来的抽屉**
（`public/js/social.js` + `css/social.css`），社区页与游戏内 HUD 都能开，
顶栏那颗「消息」按钮带未读角标。三页签：

- **好友**：在线点、备注（一条边两个人各存各的，谁加的谁叫得顺口）、私聊、看主页、解除。
  顶部直接躺着待处理请求，接受/拒绝不用换页。
- **扩列**：按关键词 + 地区 + 性别 + 性格标签找人，卡片上就写着这些，不用点进主页才知道是谁。
  默认口径是"愿意被扩列的人"（`looking` 为 `none` 的不出现），明确搜名字时带 `all=1` 才全给。
  `/friends` 那一页的「扩列」页签用的是**同一个渲染函数**（`renderPeopleGrid`），不抄第二份。
- **消息**：世界频道、当前这张图的地图频道、以及所有有往来的私聊会话（带未读）。

资料字段是四件：**地区**（34 个省级 + 港澳台 + 海外，只能选不能填）、
**性别**（男 / 女 / 其他 / 不展示，没有默认值）、**性格标签**（12 选最多 6）、
**扩列状态**（欢迎扩列 / 找固定队友 / 只聊天 / 不扩列）。
枚举表在 `public/js/profile-fields.js` 一份，服务端 import 它做校验、前端 import 它做渲染——
抄两份必然出现"前端能选、后端报非法"。默认全空：注册框不该逼人家填性别。

用户主页（`/u/<名字>`）显示一张皮肤卡：六块配色是纯 CSS 人偶、MC 展开图裁正脸、
骨骼皮肤（那台 CC0 机甲）用 `skin-rig.js` 起一个小 WebGL 预览并跟着走路循环；
旁边是地区 / 性别 / 扩列状态与性格标签。别人看你的主页，看到的就是你进图时那身。

<a id="realtime"></a>
## 联机与聊天

`server/realtime.mjs`，原生 WebSocket，零依赖。一个 `pubId` 一个房间，
**房间上限 24 人**——本地服务不是给压测用的，超了就明确拒绝而不是悄悄丢消息。

聊天分**三种频道**，都在 `server/chat.mjs` 里，一份实现三种用法：

| 频道 | 谁能看见 | 谁能在里面说话 |
|---|---|---|
| `world` 世界频道 | 所有在线的人，不管在不在某张图里 | 登录用户 |
| `map:<pubId>` 地图频道 | 这张图的玩家 + 详情页上的人 | 登录用户 |
| `dm:<对方 id>` 私聊 | 只有那两个人 | **必须是好友**（服务端判，不是界面藏按钮） |

- 频道 key 由服务端算：私聊那一对是排序后的 id 拼接，客户端只能报"我要跟谁说话"，
  报不出"任意字符串"。地图频道必须对应一件还在架上的作品，凭空开的一律拒。
- 消息**落盘**（`server/data/chat/chat.json`，原子写），是**有界环形缓冲**：
  世界 200 条、每张图 120 条、每对私聊 200 条，图最多留 80 张、私聊最多留 300 对，按最后发言时间淘汰。
- 未读只算私聊。公共频道给每个人挂红点是噪音，不是消息。
- 传输两条路、发送一条路：`POST /api/community/chat` 进来 → 存 → 推给订阅了这个频道的连接。
  游戏内的房间 socket 与社区页的 `/ws/social` 都算订阅者；没 socket 时靠 `after` 游标轮询兜底。
  同一条消息可能从两条路都到，所以前端按消息 id 去重。
- 审查与社区帖子同一道 `screen()`，限流是"同一人同一频道 900ms 冷却 + 每分钟 25 条"。

`/ws/social` 是一条**不进任何房间**的连接：社区页开着就算在线，主页上那个绿点、
别人发来的私聊推送都挂它上头。没登录连不上（401）。

游戏内的聊天面板有「地图 / 世界」两档：地图那档走房间 socket（同图的人），
世界那档走 HTTP。私聊**不进**这个面板——那是一对一的，混进公共流等于把别人的对话念出来，
要看不如打开右侧的社交抽屉。

房间同步本身照旧：加入/离开、位置与朝向、名字与外观。
协作编辑房（`edit:<世界 id>`）另走一条权威流：方块改动、实体变换、脚本内容、
以及**环境标量（昼夜 / 天气）**——所有人共用服务端定的顺序，
没有"我先改所以我对"。环境用白名单 + 取值域校验，越界的 `dayNight` 会让光照算出 NaN。

<a id="limits"></a>
## 做不到什么

写下来，免得被当成"再改改就有"：

- **不是公网服务。** 绑 `127.0.0.1`，没有 TLS，没有多租户。要给别人玩，得另做部署与鉴权。
- **没有内容分发。** 每次游玩都从磁盘拷一份快照到本地世界，10 个人玩同一张图就是 10 份。
- **文件存储不是数据库。** 并发写靠"改完立刻落盘 + 单进程"兜住，多开一个服务进程就会互相覆盖。
- **没有真正的推荐。** 广场的"热门"就是游玩次数排序，没有冷却、没有去重、没有反作弊。
- **没有离线可玩。** 断网时广场是空的，本地世界照常。

<a id="verify"></a>
## 怎么验

`test/platform.test.mjs` 走的是真实 HTTP + 真实浏览器，两个 cookie 互相隔离的上下文
（`Session.open(port, { isolated: true })`），所以"用户 A 做事、用户 B 也在做事"是被真的跑出来的：
注册两个账号、A 发布、B 点赞评论、A 看到计数、B 改昵称后 A 那边同步刷新。
