# 社区层

编辑器造图，运行时跑图，社区层让人把图**发给别人**。这三件事里只有第三件是新的，
所以它也是最容易做假的一件：挂个列表页、放几张卡片，看着像社区，其实是个文件管理器。

这一篇写清楚社区层到底有什么、每个决定的代价，以及**它做不到什么**。

<a id="scope"></a>
## 一句话范围

账号、会话、关注、好友、地图/模型发布快照、广场与详情、点赞、评论、举报、
图片上传、封面生成、后台审查面板、多人联机与内置聊天——全部跑在**同一台本机 Node 进程**里，
零第三方依赖，数据是 `DATA_ROOT/community/` 下的 JSON 文件。

没有数据库，没有 Redis，没有对象存储，没有 CDN，没有邮箱验证，没有第三方登录。
这不是偷懒，是这条产品线的前提：数据不出机器。

<a id="identity"></a>
## 账号与会话

| 项 | 值 | 为什么 |
|---|---|---|
| 昵称 | 2–20 字符，中英文/数字/空格/`_`/`-` | 要能显示在角色头顶，太长会把 HUD 撑破 |
| 昵称唯一 | 大小写不敏感，改名不能撞别人 | 主页 URL 是 `/u/<名字>`，不唯一就寻址不了 |
| 密码 | scrypt，参数随凭据一起存 | 没有 bcrypt/argon2 可用，Node 内置只有 scrypt |
| 会话 | 随机 token，`HttpOnly + SameSite=Lax`，30 天 | 本机服务，但 SameSite 仍然要设，CSRF 面一样存在 |
| CSRF | 读接口下发 `ly_csrf` cookie，写请求必须原样带回 `X-CSRF-Token` | cookie 是 `Lax` 而不是 `None`，所以跨站表单打不进来 |
| 封禁 | `role: admin` / `banned` 标记，被封的账号只读 | 后台要能收得住捣乱的人，又不至于把机器锁死 |

会话校验顺带清理过期 token：`now() - createdAt > SESSION_TTL` 的会话在**任何一次请求**里
被碰到就删掉。没有后台定时任务，因为一个会自己醒的进程在这套架构里是额外复杂度。

<a id="publish"></a>
## 发布：快照，不是引用

这是社区层最重要的一个决定。

**发布不指向世界，而是把世界复制出去。** `POST /api/community/publish` 会把
`payload`、实体、脚本、素材目录整个拷进 `community/pubs/<pubId>.json.gz`（一个扁平文件，
封面与素材是它的同名旁文件），之后作者改自己的图，别人点进去看到的还是发布那一刻的样子。

代价是磁盘：一张 4.5 MB 的图发一次就占 4.5 MB。换来的是两件更要紧的事：

1. 玩家点「开始游玩」不会拿到一张作者改到一半、正在报错的图。
2. 作者删掉本地世界，社区里那张图不会跟着变成 404。

再往上就是**版本**：重复发布同一个 `worldId` 会把上一份归档进 `versions`，
`version` 自增，详情页显示"版本 N"和每条更新说明（≤200 字）。
不做 diff、不做回滚合并——快照链已经够用，diff 会引入一套自己的正确性负担。

`kind` 有 `map`、`model`、`skin` 三种。模型走 `.voxa.json`，8 MB 上限，取回是**并进本地模型库**
而不是覆盖，同名会另存。

### 详情页那四个读数

`pubCard` 一张卡带出四种计数，全部是真读数，没有一个是装饰：

| 读数 | 从哪来 | 空的时候显示什么 |
|---|---|---|
| 正在玩 | `createCommunity({ presence })` 回调问 `realtime` 要 `pub:<id>` 房间的人数 | `0`，绿点是灰的 |
| 累计进入 | `POST pubs/<id>/play` 计数（同时写进「最近游玩」） | `0` |
| 收藏 | `pubs/<id>/favorite` 的用户数组长度 | `0` |
| 好评率 | `pubs/<id>/vote` 的 `up/(up+down)`，四舍五入 | **暂无评分**，并且不给那根条 |

两条刻意的取舍：**一票没有时不给百分比**（写"0%"或"100%"都是编的），
**改版不清票**（否则每张迭代过的图都退回"暂无评分"）。
`playing` 缺注入时返回 `0` 而不是 `undefined`——前端拿到 undefined 会渲染成空白，
看起来像坏了，而不是"这里没人"。

## 皮肤社区：第三种发布

皮肤既不是地图也不是模型：它没有"游玩"这个动作，也不该被塞进模型流里沉底。
所以它是第三种 `kind`，走同一套发布、点赞、评论、版本与举报，只换动作。

- **记录**：`.skin.json`（六块色 + 可选贴图 / 骨骼映射），≤64 KB。
- **资产**：贴图 PNG 与骨骼 GLB 以 base64 附件收进这份发布自己的 `.assets/`，
  记录里的路径被改写成 `/api/community/pubs/<id>/asset?path=…`。不改写的话，
  别人下载到的皮肤指向作者本机的世界目录，作者一删图就 404。
- **取用**：详情页的主按钮是「应用到我的角色」——写进**账号皮肤**，
  于是进任何一张图都这一身，联机时别人看你也是；不是"复制一份到这张图里"。
- **白名单**：外链资产、坏颜色、坏轴向、离谱缩放一律丢掉；认不出至少 6 根关节的
  记录不当它是骨骼皮肤。宁可退回纯色人偶，也不要半台机甲只躯干跟着动。
- 皮肤库面板里每张卡的「⋯」可以发布，工具条的「皮肤社区」可以取回：
  取回时资产会**复制进本图资产目录**，作者之后下架不影响你已经装上的这套。

<a id="surfaces"></a>
## 前端有哪几个面

路由是同一套壳（`community.html`）按 `location.pathname` 分派，`popstate` 重跑：

| 路径 | 是什么 |
|---|---|
| `/community` | 广场：精选位 + 导轨 + 分类 + 排序 + 搜索。**筛选状态在地址栏里**（`?sort=&cat=&kind=&q=`） |
| `/p/<pubId>` | 地图/模型详情：封面压标题、右栏动作与信息表、评论、"接下来试试" |
| `/u/<名字>` | 用户主页：横幅（没设过的用最近那张图的封面垫底）、头像、皮肤卡（与进图同一具 3D 人偶 + 非默认体型读数）、地区·性别·性格、关注/加好友/私聊、地图/模型/关注者/关注中/收藏/最近游玩六个 tab（**当前页签在 `?tab=` 里**，能深链、刷新不丢）。关注者/关注中每行带在线点与「关注 / 已关注」——看到有人跟着我，回关不该要点三次 |
| `/friends` | 好友与关注：好友（在线优先 + 状态点）/ 请求 / 扩列 / 可能认识（带"N 个好友在跟"）/ 通知（好友请求可就地接受） |
| `/me` | 自己的主页（未登录会跳登录框） |

广场的卡片是**图占绝对主导**的展厅读法：标题压在封面下缘的暗带上，
相框 16:10 用 `contain`——这些封面是体素小地图，`cover` 会裁掉一圈看不出是什么，
而 1:1 方框配 16:9 原图只剩上下两道黑带。

### 广场的筛选状态存在地址栏里

以前只存在内存，于是导轨上那句「按热度看 → `/community?sort=hot`」是个假链接：
点进去地址变了、视图却还是最新。搜索结果同样没法分享、没法后退。
现在 `feedView()` 进来先 `readFeedUrl()`，切 tab / 点分类 / 搜索时 `writeFeedUrl()` 写回。

**用 `replaceState` 而不是 `pushState`**：切一次页签就压一条历史的话，
后退键会变成"回到我三分钟前点过的那个分类"，没人想要那个。
`cat` 不做本地白名单——服务端 `CATEGORIES.includes()` 不认的会直接忽略，
两边各维护一份清单必然漂。

### 好友这一页，每一行都得说得出为什么

`/friends` 五个页签，判据都是同一句话：**这行为什么出现在这里**。

- **好友**：在线的排前面，其次按发布数。这一页问的是"现在能拉谁一起玩"。
  状态是一个绿点（`.cm-on`）而不是"· 在线"那两个字——扫一眼就知道，不用读。
- **可能认识**：`GET /api/community/friends` 的 `suggested[]` 每项带 `mutual`
  （**我的好友里有几个人跟了 TA**），列表按它排序，前端写成"1 个好友在跟"。
  只有名字没有理由的推荐位，和随机抽人没区别。
- **通知**：`friend_request` 那一条就地给「接受 / 拒绝」，不用先跳页签。
  但通知是**日志不是待办**，所以两件事要分开处理：
  按钮只在 `incoming` 里还有这个人的时候才画（否则点下去只会拿到"你们已经是好友了"），
  而翻过篇的那条按真实状态改口成"的好友请求已通过 / 已处理"。
  页签上那个 `(1)` 角标在标记已读的响应回来时就改掉——挂着不清是个假读数。
- **解除好友**要二次确认。抽屉里那条一直有，这一页以前点一下就没了：
  同一件事在两个入口代价不一样，就是漏写。

<a id="moderation"></a>
## 评论、审查与举报

评论 500 字上限，一层平铺（没有楼中楼：记录里只有 `pubId / userId / body / likes`，
歪楼在一张地图的评论区里只会让顺序更难读），点赞去重按用户。
**未登录也给出一个禁用的输入框**，而不是"登录后才能评论"一句话——
位置先占住，用户知道这里能写。
自己的评论给「删除」，别人的给「举报」；这张地图作者本人的评论挂一颗「作者」芯片
（`commentCard.author.id` 对上 `pubCard.author.id` 就点亮）——一个几十条的楼里，
哪句是作者说的不该靠翻主页去对。

文本进来先过 `screen()`：`block` 词表直接拒，`flag` 词表放行但打 `flagged` 标记，
后台面板按标记排序给人看。词表在 `community/mute-words.json`，改完 **mtime 变了就热加载**，
不用重启服务。

举报进 `reports` 队列，上限 500 条，超了丢最老的。后台能直接下架（`status` 从 `live` 改成别的），
下架的发布对所有读接口立刻不可见。

封面：发布时如果没带封面，服务端会用体素数据**离线渲染一张**（带邻接遮蔽的明暗），
所以不会出现"每张图都缺一个 404 占位"的场面。

<a id="social"></a>
## 好友、扩列与资料

社交动作大多发生在"正在做别的事"的时候：逛广场看到一个人、玩图时想喊一句、
收到请求想立刻回。所以它不是一个页面，而是**从右侧滑出来的抽屉**
（`public/js/social.js` + `css/social.css`），社区页与游戏内 HUD 都能开，
顶栏那颗「消息」按钮带未读角标。三页签：

- **好友**：在线点、备注（一条边两个人各存各的，谁加的谁叫得顺口）、私聊、看主页、解除。
  顶部直接躺着待处理请求，接受/拒绝不用换页。
- **扩列**：按关键词 + 地区 + 性别 + 性格标签找人，卡片上就写着这些，不用点进主页才知道是谁。
  默认口径是"愿意被扩列的人"（`looking` 为 `none` 的不出现），明确搜名字时带 `all=1` 才全给。
  `/friends` 那一页的「扩列」页签用的是**同一个渲染函数**（`renderPeopleGrid`），不抄第二份。
- **消息**：世界频道、当前这张图的地图频道、以及所有有往来的私聊会话（带未读）。

资料字段是四件：**地区**（35 项 = 31 个省级 + 香港 / 澳门 / 台湾 + 海外，只能选不能填）、
**性别**（男 / 女 / 其他 / 不展示，没有默认值）、**性格标签**（12 选最多 6）、
**扩列状态**（欢迎扩列 / 找固定队友 / 只聊天 / 不扩列）。
枚举表在 `public/js/profile-fields.js` 一份，服务端 import 它做校验、前端 import 它做渲染——
抄两份必然出现"前端能选、后端报非法"。默认全空：注册框不该逼人家填性别。

用户主页（`/u/<名字>`）显示一张皮肤卡，三种皮肤共用 `avatar.js` 那一具人偶：
纯配色与 MC 展开图都走 `makeAvatar()`（贴图那件由 `skin3d.js` 换材质），骨骼皮肤
（那台 CC0 机甲）由 `skin-rig.js` 装成同一份 parts 契约，两者都跟着走路循环动。
旁边是地区 / 性别 / 扩列状态与性格标签。以前非骨骼皮肤在这里是一张**纯 CSS 纸片人**，
于是"主页上的我"和"进图之后的我"是两种画法——现在只有一份，漂移不了；
CSS 那张退成 WebGL 起不来时的兜底。

### 体型三档

账号皮肤除了五键配色，还带一个 `body: { h, w, leg }`——身高 / 宽窄 / 腿长，
取值 **0.80~1.25** 的乘数（编辑资料里那三根滑杆给的是 80~125，存的是除以 100）。

- 存在账号上而不是地图里：身材是"我是谁"，进谁的图都该带着走。
  联机那边 `welcome.peers[].skin` 原样透传，所以同伴看到的也是这个身材。
- 乘在 `makeAvatar()` 内部新加的 `bodyRoot` 上，**不是**返回值本身——
  外层 scale 归 `player.scale` 用（运行时每帧按它 `setScalar` 写一遍），
  抢过来就是"调了体型之后玩家缩放失效"或者反过来被每帧覆盖。
- 腿长绕髋（y=0.80）放大之后必须把躯干/头/手臂整体抬起来，`rig.base` 三个基准高度
  跟着改：`poseWalk` 按 base 写绝对高度，不改就是走路时上半身和腿脱开。
- 服务端 `normalizeSkin` 把越界值**夹回**量程而不是拒掉整份皮肤；全 1 时干脆不存这个键，
  否则以后想挪默认身材得先迁移几百个账号。
- 预览的机位按身高一起拉远（`stage.frame(k)`），否则 1.25 身高会被画布裁掉一颗头。
  判据也因此取**竖直跨度**：脚下那颗接触阴影盘不参与体型缩放，量宽度会得到一个假失败。

<a id="realtime"></a>
## 联机与聊天

`server/realtime.mjs`，原生 WebSocket，零依赖。一个 `pubId` 一个房间，
**房间上限 24 人**——本地服务不是给压测用的，超了就明确拒绝而不是悄悄丢消息。

聊天分**三种频道**，都在 `server/chat.mjs` 里，一份实现三种用法：

| 频道 | 谁能看见 | 谁能在里面说话 |
|---|---|---|
| `world` 世界频道 | 所有在线的人，不管在不在某张图里 | 登录用户 |
| `map:<pubId>` 地图频道 | 这张图的玩家 + 详情页上的人 | 登录用户 |
| `dm:<对方 id>` 私聊 | 只有那两个人 | **必须是好友**（服务端判，不是界面藏按钮） |

- 频道 key 由服务端算：私聊那一对是排序后的 id 拼接，客户端只能报"我要跟谁说话"，
  报不出"任意字符串"。地图频道必须对应一件还在架上的作品，凭空开的一律拒。
- 消息**落盘**（`server/data/chat/chat.json`，原子写），是**有界环形缓冲**：
  世界 200 条、每张图 120 条、每对私聊 200 条，图最多留 80 张、私聊最多留 300 对，按最后发言时间淘汰。
- 未读只算私聊。公共频道给每个人挂红点是噪音，不是消息。
- 传输两条路、发送一条路：`POST /api/community/chat` 进来 → 存 → 推给订阅了这个频道的连接。
  游戏内的房间 socket 与社区页的 `/ws/social` 都算订阅者；没 socket 时靠 `after` 游标轮询兜底。
  同一条消息可能从两条路都到，所以前端按消息 id 去重。
- 审查与社区帖子同一道 `screen()`，限流是"同一人同一频道 900ms 冷却 + 每分钟 25 条"。

`/ws/social` 是一条**不进任何房间**的连接：社区页开着就算在线，主页上那个绿点、
别人发来的私聊推送都挂它上头。没登录连不上（401）。

游戏内的聊天面板有「地图 / 世界」两档：地图那档走房间 socket（同图的人），
世界那档走 HTTP。私聊**不进**这个面板——那是一对一的，混进公共流等于把别人的对话念出来，
要看不如打开右侧的社交抽屉。

房间同步本身照旧：加入/离开、位置与朝向、名字与外观。
协作编辑房（`edit:<世界 id>`）另走一条权威流：方块改动、实体变换、脚本内容、
以及**环境标量（昼夜 / 天气）**——所有人共用服务端定的顺序，
没有"我先改所以我对"。环境用白名单 + 取值域校验，越界的 `dayNight` 会让光照算出 NaN。

三条 socket 路径，都在 `server/realtime.mjs` 里按路径前缀分派：

| 路径 | 房间 | 用途 |
|---|---|---|
| `/ws/play/<pubId>` | `play:<pubId>` | 游玩同一张图的人 |
| `/ws/edit/<worldId>` | `edit:<worldId>` | 编辑器协作（权威流） |
| `/ws/social` | 不进房间 | 在线状态 + 世界频道 / 私聊推送 |

<a id="api"></a>
## 接口一览

HTTP 全在 `/api/community/` 下（`server/community.mjs`）。标 ★ 的要先登录，
且写操作要带 `x-csrf-token`（与 `ly_csrf` cookie 双提交比对）。

| 路径 | 方法 | 做什么 |
|---|---|---|
| `me` | GET / PATCH ★ | 当前用户；PATCH 收 `name / bio / avatar / banner / skin` 与四件资料字段 |
| `register` `login` `logout` | POST | 账号与会话（`ly_session`，HttpOnly，30 天） |
| `upload?kind=` | POST ★ | 图片上传，kind ∈ cover / avatar / banner / preview / skin |
| `uploads` | GET | 列自己传过的图 |
| `users/...` | GET | 公开主页数据（按 id 或 `?name=`）；`?all=1` 才带出"不扩列"的人 |
| `follow` | POST ★ | 关注 / 取关 |
| `friends` | GET ★ | 好友、待处理请求、可能认识（`suggested[].mutual` = 我的好友里有几个人跟了 TA） |
| `friend/request\|accept\|decline\|remove\|note` | POST ★ | 好友关系；`note` 写**单向备注**（只有你自己看得到） |
| `people` | GET | 扩列发现：按地区 / 性别 / 性格筛，默认只给"愿意被扩列"的 |
| `chat` | GET / POST ★ | 读频道历史（`?ch=&after=`）/ 发一条 |
| `chat/read` | POST ★ | 把某个频道的未读清零 |
| `channels` | GET ★ | 抽屉一次拿全：各频道未读数 + 私聊会话列表 |
| `feed` | GET | 广场分页，`kind=map\|model\|skin`、`cat`、`sort=new\|hot\|following\|foryou`。**这四个参数同时是 `/community` 的地址栏状态**：`?sort=hot&cat=竞速` 可以直接分享、刷新不丢 |
| `users/<名字>/pubs` | GET | 某人发布的作品，`?kind=` 可选 |
| `users/<名字>/favorites` | GET | 某人收藏的作品。**只有本人与管理员读得到**（403，不是空列表——空列表会诱导人去猜） |

<a id="limits"></a>
## 做不到什么

写下来，免得被当成"再改改就有"：

- **不是公网服务。** 绑 `127.0.0.1`，没有 TLS，没有多租户。要给别人玩，得另做部署与鉴权。
- **没有内容分发。** 每次游玩都从磁盘拷一份快照到本地世界，10 个人玩同一张图就是 10 份。
- **文件存储不是数据库。** 并发写靠"改完立刻落盘 + 单进程"兜住，多开一个服务进程就会互相覆盖。
- **没有真正的推荐。** 广场的"热门"就是游玩次数排序，没有冷却、没有去重、没有反作弊。
- **没有离线可玩。** 断网时广场是空的，本地世界照常。

<a id="verify"></a>
## 怎么验

`test/platform.test.mjs` 走的是真实 HTTP + 真实浏览器，两个 cookie 互相隔离的上下文
（`Session.open(port, { isolated: true })`），所以"用户 A 做事、用户 B 也在做事"是被真的跑出来的：
注册两个账号、A 发布、B 点赞评论、A 看到计数、B 改昵称后 A 那边同步刷新。
